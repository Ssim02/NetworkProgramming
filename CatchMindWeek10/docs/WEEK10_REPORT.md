## 이번 주 개발 내용
중앙 그림판과 양쪽 네 개의 참가자 카드, 하단 채팅창으로 기본 화면을 구성했다.
그림은 BufferedImage에 저장하여 화면이 다시 그려져도 유지되도록 설계했다.
색상·굵기·전체 지우기를 제공하며 흰색 펜을 지우개로 사용한다.
TCP 연결 후 JOIN_OK를 수신해야 채팅 입력을 활성화한다.
서버가 전달한 PLAYERS 메시지로 참가자 카드를 갱신한다.

## 핵심 코드와 처리 흐름
접속 버튼 → 별도 작업 스레드에서 Socket 연결 → JOIN 전송 → JOIN_OK 확인 → 수신 스레드 시작.
채팅 전송 → 서버 검증 → 전체 참가자에게 CHAT_MSG 전송 → 수신 스레드에서 읽기 → EDT에서 화면 반영.
readUTF는 데이터를 기다리므로 화면 이벤트를 처리하는 EDT와 분리했다.
SwingUtilities.invokeLater는 수신 결과를 EDT에 넘겨 안전하게 Swing 컴포넌트를 갱신한다.
서버의 synchronized 전송은 같은 클라이언트의 출력 스트림에 여러 스레드가 동시에 쓰는 것을 방지한다.

## 실제 검증 결과
AI 지원 개발 환경에서 JDK 21로 컴파일했고 다음 자동 테스트를 통과했다.
영문·한글 채팅 전달, 참가자 목록, 중복 닉네임 거부, 4명 정원 제한,
잘못된 명령어·200자 초과 채팅 거부, 퇴장 후 이름 재사용, Swing 화면 생성·렌더링.
원본 로그: evidence/test-results.txt. 화면: evidence/client-preview.png.
테스트는 실제 TCP 연결을 사용했다. 두 GUI를 직접 조작한 통합 테스트와 마우스 동작 확인은 남아 있다.

## 문제와 조치
Wireshark 루프백 캡처를 시도했으나 관리자 전용 Npcap 드라이버 권한 오류로 수집하지 못했다.
따라서 패킷 분석은 미완료로 구분한다. 사용자 환경에서 관리자 권한으로 Wireshark를 실행하고
tcp.port == 5000 필터로 접속·채팅 흐름을 확인할 예정이다.
